# Auvix Studio — промо-ролик

Анимационный ролик о студии: 50 секунд, 1080×1920 (9:16), 30 fps, со звуком.

Видео не монтируется в редакторе — оно **рендерится из кода**. Сцена написана
на HTML/CSS/JS, Playwright снимает её покадрово, ffmpeg собирает MP4.
Поэтому правка текста — это правка одного файла и повторный запуск сборки,
а не переделка проекта в After Effects.

## Сборка

```bash
./build.sh                 # 30 fps → out/auvix-studio-30fps.mp4 (~18 МБ)
FPS=60 ./build.sh          # 60 fps
CRF=20 ./build.sh          # архивное качество (файл в ~5 раз тяжелее)
SHARDS=2 ./build.sh        # меньше параллельных процессов (слабая машина)
```

Зерно на кадре некоррелировано между кадрами и почти целиком определяет
битрейт: на CRF 20 файл весит около 190 МБ, на CRF 26 — 18 МБ, при этом на
мелком тексте разница не видна. Отсюда дефолт CRF 26.

Нужны `node` (с установленным `playwright`), `python3` c `numpy` и `ffmpeg`.
Рендер шардируется по числу ядер: на 4 ядрах 30 fps собирается примерно
за 4–5 минут.

## Как поменять тексты

Всё содержимое ролика лежит в [`src/content.js`](src/content.js) — услуги,
реплики бота, кейсы, цифры, контакты. Ничего, кроме этого файла, для смены
текстов трогать не нужно.

```js
services: [
  { n: '01', title: 'САЙТЫ\nИ ЛЕНДИНГИ', note: 'дизайн · вёрстка · запуск', art: 'ring' },
  ...
]
```

`\n` — принудительный перенос строки. `art` выбирает хром-объект на карточке:
`ring`, `blob`, `wave`, `knot`, `grid`, `orb`.

**Кейсы в `cases` сейчас заполнены примерами.** Их нужно заменить настоящими
проектами и цифрами перед публикацией.

## Как поменять цвета

Палитра — CSS-переменные в начале [`src/style.css`](src/style.css):

```css
--bg:#05070A;      /* фон                       */
--lime:#C6F132;    /* основной акцент           */
--flash:#E4FF57;   /* вспышки на склейках       */
--ink:#F4F7EE;     /* текст                     */
--mute:#8A9480;    /* подписи                   */
```

## Как поменять тайминги

Раскадровка задана в [`src/blocks.js`](src/blocks.js) вызовами
`block(имя, начало, конец, ...)`:

| Секунды | Блок | Что происходит |
|---|---|---|
| 0–6 | `hook` | Три фразы кинетическим текстом |
| 6–8 | `sting` | Монограмма прорисовывается штрихом |
| 8–16 | `services` | 3D-барабан из шести карточек услуг |
| 16–22 | `site` | Мокап телефона: сайт собирается сам |
| 22–33 | `bot` | Диалог с ботом, затем отъезд камеры к схеме интеграций |
| 33–36 | `bridge` | Текстовый мост |
| 36–42 | `cases` | Сетка работ → раскрытие карточки со статистикой |
| 42–45 | `process` | Карусель этапов работы |
| 45–50 | `final` | Призыв, частицы, логотип, контакты |

Массив `CUTS` в том же файле — точки склейки. По ним бьёт вспышка **и**
расставлены удары в звуке, поэтому менять их нужно в паре с `CUTS`
в [`audio.py`](audio.py).

## Звук

[`audio.py`](audio.py) синтезирует подложку с нуля: 120 BPM, бас-пульс,
хэты, арпеджио на демо-блоках, райзер перед логотипом. Такт — ровно 2 секунды,
и все склейки монтажа стоят на чётных секундах, поэтому картинка и звук
сходятся без ручной подгонки.

Чтобы поставить свой трек вместо синтезированного — положите файл в
`out/audio.wav` и запускайте сборку без шага `python3 audio.py`.

## Устройство рендера

Ключевое ограничение: **никаких CSS-анимаций и `requestAnimationFrame`**.
Состояние сцены — чистая функция от времени (`window.seek(t)`), поэтому
Playwright может шагать по кадрам сколь угодно медленно, а результат совпадает
с воспроизведением в реальном времени. Кадры независимы — отсюда и возможность
рендерить их параллельно в несколько процессов.

- [`src/engine.js`](src/engine.js) — easing-функции, работа с текстом,
  генератор хром-объектов, курсор.
- [`src/blocks.js`](src/blocks.js) — сами блоки: каждый строит DOM один раз,
  а дальше только переписывает `transform` и `opacity`.
- [`render.mjs`](render.mjs) — покадровая съёмка, поддерживает
  `--preview 3.5,12,40` для быстрой проверки отдельных моментов.

Хром-объекты собраны из `conic-gradient` и SVG-фильтра искажения, а не из
3D-рендеров: они векторные, ничего не весят и перекрашиваются вместе с палитрой.
